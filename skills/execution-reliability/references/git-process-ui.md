# Git、进程与 UI

## Git

先确认真实仓库根、当前分支、`HEAD`、工作树和是否处于 nested repository/worktree。发布或提交前核对目标仓库和远端；不要因当前目录看起来像项目就推断其 Git 身份。

## 进程与端口

端口冲突先查询监听 PID、命令行、启动时间和父进程，判断是否属于当前任务。没有所有权证据时只报告冲突，不终止进程。重新启动前记录旧实例是否仍提供用户可见服务，避免把旧版本响应当成新版本验证。

## UI 自动化

每个关键动作前重新观察当前页面、窗口、焦点和控件可用性。截图、DOM 快照或旧坐标只是历史证据，不能直接重放。操作后验证可见状态和实际后端结果；页面无响应时区分提交未发生、请求在途、后端失败和结果未刷新四种情况。
