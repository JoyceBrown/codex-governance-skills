# Windows 与路径配方

## 选择命令表面

- 已知参数优先使用 PowerShell 命令的参数形式，不拼接未经转义的长字符串。
- 文件路径使用 `-LiteralPath`；需要多个路径时传数组，不依赖通配符。
- 需要调用外部程序时，把可执行文件和参数分别传递；不要把带引号的整段命令交给另一层 shell 再解析。
- 只在确实需要 CMD 语法时使用 `cmd.exe /d /s /c`，并先记录这是额外解析层。

## 编码与目录

- 脚本和发布文本使用 UTF-8；不要用系统默认代码页读写配置或 JSON。
- 中文路径不是错误条件。只有工具明确不支持、解析结果与预期不一致、路径过长或构建工具把源码/产物混用时才升级。
- 记录绝对路径和路径长度，但收据只保留脱敏标签或摘要，不复制用户目录和私有路径。
- 需要临时目录时使用系统临时目录或项目已声明的临时目录；不要把构建输出写进源码目录。

## 变量传播

先识别真正执行构建的进程链：工作台 -> shell -> package script -> builder。变量必须在最终启动器可见的进程环境中设置，并用非敏感键名和结果做一次确认。Electron 构建变量和 electron-builder 变量可能属于不同进程，不能以其中一层成功推断另一层成功。
