# Code review routing

`deliberate-project` 可以承担高风险或架构性代码审查，但不接管日常代码检查。按风险选择审查强度：

| 级别 | 路径 | 适用场景 |
| --- | --- | --- |
| L1 | Codex 原生 review | 普通小改动、局部修复、常规测试变更 |
| L2 | 独立代码审查 | 主要功能、复杂 Bug、较大重构或需要第二视角的变更 |
| L3 | 三堂会审 + 独立代码审查 | 跨模块架构变化、认证授权、迁移、并发、数据完整性、发布前高风险变更 |

代码审查请求至少携带：需求或验收引用、`BASE_SHA`、`HEAD_SHA`、实际 diff、重点风险和需要查看的不变上下文。审查结果至少返回：`file:line` 证据、严重级别、需求偏差、实现缺陷、架构疑点、测试缺口和合并就绪判断。

独立审查是能力类型，不是必需 Skill。Codex 原生 review 是默认实现；如果宿主提供兼容的外部能力（例如 `requesting-code-review`），可以在同一请求信封内使用；缺少外部能力时回退到原生 review 或当前角色内的等价检查。外部能力不能取得计划、授权、账本或最终裁决权。

三堂会审只在用户明确要求时启动。它负责综合目标、边界、证据和争议，独立代码审查只提供代码级证据；两者都不能把“测试通过”自动升级为用户目标已接受。
