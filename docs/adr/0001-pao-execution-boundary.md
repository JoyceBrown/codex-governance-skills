# ADR 0001: PAO 执行边界

## 决定

PAO 以当前会话和唯一项目计划为执行权威。内部辅助和可选 app-server bridge 是开发增强能力；它们没有项目事实、授权或第二计划的所有权。没有真实宿主能力时，桥接返回 `capability_gap`，当前会话仍可用 standalone 流程开发。

## 原因

把宿主桥接代码留在历史资料会造成文档与实现矛盾；把它当成必需运行时又会让普通本地开发因宿主缺失而阻塞。因此能力可用性必须显式探测，结果必须可降级。

## 后果

PAO 可以在有共享 app-server 端点时派发短期开发任务；不能假设 Codex 桌面一定暴露该端点，也不能把模拟 transport 的测试当成真实宿主验证。
